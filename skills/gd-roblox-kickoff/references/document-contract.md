# Контракт документов для Roblox MVP

Документация должна быть понятна геймдизайнеру, программисту и QA. Не переусложняй ради оформления.

## docs/project-concept.md

- Название и дата
- Короткий питч (1–3 предложения)
- Роль игрока, фантазия, целевая аудитория (известное / предположение)
- Core loop: вход → действие → результат/награда → повтор
- Главный интерес/USP и критерий успеха теста
- Визуальный стиль и ракурс; разрешены простые Parts
- MVP: включено/исключено
- Дальше P1 и P2
- Ограничения, решения пользователя, допущения и открытые вопросы

## docs/feature-index.md

Таблица: ID | Фича | Для игрока | Приоритет (MVP/P1/P2) | Зависимости | Статус (idea/ specified/ implementing/ tested) | Документ.

Фичи MVP должны вместе давать один играбельный цикл. Стабильные ID нужны для привязки к коду и тестам.

## docs/features/F-001_core-loop_gd-spec.md

- ID, название, статус документа
- Цель и ощущение игрока
- Точка входа, действия и результаты
- Конкретные правила и состояния
- Ошибки, пограничные случаи, повтор
- Нужные объекты мира и сигналы игроку (без инструкций по классам)
- Баланс/значения: явно помечать дефолты-предложения
- Acceptance criteria: наблюдаемое поведение
- Открытые вопросы, риски, зависимости

## docs/mvp-handoff.md

- Status: ready-for-build или decision-needed
- Ссылка на концепт, feature index и GD spec
- Hypothesis и one-session success criteria
- Scope и Out of scope
- Игровой сценарий 3–6 шагов
- 3–7 проверок DoD
- Допустимые placeholder-ассеты
- Нерешённые решения с критичностью
- Тест: локально в Studio, без обязательного publish

Если документы уже есть, обновляй их небольшими правками и соблюдай имена/ID проекта, а не дублируй новые копии.
