# RobloxGameKit — создание игр Roblox с помощью Codex

**Что это:** набор шаблонов, готовых модулей и инструкций, который помогает Codex создавать Roblox-игры по твоей идее. Код хранится в папке на компьютере, а сцену и игровой мир ты видишь в **Roblox Studio**.

**Какой результат:** сначала небольшой играбельный прототип (MVP), затем развитие **этого же проекта** до полноценной игры: серверные системы, сохранения, лобби, мультиплеер, тесты и подготовка к публикации.

> Это **не отдельный игровой движок** и не кнопка «сделать всю игру». Codex создаёт скрипты и может работать со Studio, если настроены нужные инструменты. Ты проверяешь результат в Roblox Studio.

## 1. Как устроен процесс

| Этап | Что делает Codex | Что получаешь |
|---|---|---|
| **1. GDD — идея** | Слушает твою идею, уточняет правила, записывает концепт и список фич | `docs/project-concept.md`, `docs/feature-index.md`, описание главной механики |
| **2. MVP — первый прототип** | Создаёт простые объекты и Luau-скрипты, подключает их к Roblox Studio, запускает тест | Играбельный core loop и локальный `.rbxl` / `.rbxlx` |
| **3. Продолжение разработки** | Берёт следующую фичу из индекса; делает инвентарь, экономику, прогрессию, сохранения и UI | Расширенная **та же** игра, без пересоздания |
| **4. Онлайн-режим** | Добавляет серверную логику, лобби, мультиплеер, телепорты, проверки | Тестируемый онлайн-проект |
| **5. Релиз** | Проверяет безопасность, производительность, устройства и готовность к публикации | Игра, готовая к твоему решению о публикации |

**Принцип:** каждый этап можно запускать голосом в Codex. Не нужно начинать проект заново после MVP.

## 2. Какие два скилла используются

1. **`$gd-roblox-kickoff` — геймдизайнер.** Из устного описания делает концепт, Feature Index, спецификацию основной механики и документ передачи разработчику. Основан на подходе [gd-doc-kickoff](https://github.com/VKSpaz/gd-doc-kickoff), но, в отличие от оригинала, работает и с идеей всей игры.
2. **`$roblox-mvp-builder` — разработчик Roblox.** Читает документы, собирает первый прототип, а после твоей команды продолжает создавать сервисы и новые фичи вплоть до подготовки релиза. Название навыка осталось прежним для совместимости с командами.

**Где они находятся:** `skills/`. Если папки или установщика ещё нет в `main`, открой [изменения с двумя скиллами (PR № 1)](https://github.com/Tallmann999/RobloxGameKit_v0.1.0/pull/1) и прими их — после объединения они появятся в основной ветке.

## 3. Установка на Windows — один раз

**Понадобятся:** Git, Python, Codex с доступом к папке проекта, Roblox Studio. Для дальнейшей автоматической синхронизации — **Rokit, Rojo и плагин Rojo для Studio**. Для прямых действий Codex со сценой — работающий **Roblox Studio MCP**. Инструменты Rojo, StyLua и Selene будут ставиться отдельно в конкретный игровой проект.

### Шаг 1. Скачай RobloxGameKit

Открой **PowerShell**, выполни:

```powershell
git clone https://github.com/Tallmann999/RobloxGameKit_v0.1.0.git
cd RobloxGameKit_v0.1.0
```

Если ранее уже скачал репозиторий, открой его папку и обнови файлы из GitHub (`git pull`).

### Шаг 2. Установи оба скилла Codex

После того как изменения из **PR № 1** попали в скачанную версию, запусти:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install_voice_mvp_skills.ps1
```

Скрипт копирует два скилла в папку `C:\Users\<имя>\.agents\skills\`. При наличии Git отдельно получает исходный `gd-doc-kickoff` и его справочные материалы. Ранее установленные одноимённые скиллы не стирает без копии — создаёт резервную версию.

**После установки перезапусти Codex.** Если команда сообщает, что файла нет, скорее всего, ты скачал `main` до объединения PR № 1.

### Шаг 3. Проверь Studio

Установи/открой Roblox Studio. Потребуется настроить связь с Codex через **Studio MCP** и с папкой скриптов через **Rojo**. Если чего-то нет, попроси Codex проверить установку и дать точные действия; навыки не могут включить эти приложения одним лишь текстом.

## 4. Создание первой игры — просто скажи Codex

Создай **новую пустую папку игры** (например, `D:\Roblox\MyGame`), открой её в Codex и произнеси или вставь:

```text
$gd-roblox-kickoff
У меня идея Roblox-игры. Сейчас я расскажу её голосом.
Помоги оформить концепт, Feature Index и самую важную
механику. Сначала выберем маленький MVP.
```

Codex должен записать в **эту же папку игры**:

- `docs/project-concept.md` — что за игра и зачем в неё играть;
- `docs/feature-index.md` — список всех фич с приоритетами **MVP / P1 / P2**;
- `docs/features/..._gd-spec.md` — правила главной механики;
- `docs/mvp-handoff.md` — что конкретно нужно сделать для прототипа.

Не обязательно диктовать большое техническое задание. Расскажи идею обычными словами; Codex задаст несколько уточняющих вопросов.

## 5. Собираем локальный MVP

Когда документы готовы, в **той же папке** скажи:

```text
$roblox-mvp-builder
Документы готовы. Прочитай концепт и Feature Index.
Через RobloxGameKit собери только основную механику.
Подключи Roblox Studio через MCP и Rojo, сделай простую сцену,
запусти Play Test, проверь Output и сохрани локальный .rbxl.
Пока НЕ публикуй игру.
```

Codex должен проверить инструменты, создать код, подобрать минимальные модули и провести настоящий Play Test, когда Studio доступен. Если для настройки нужен клик или вход в аккаунт — он даст пошаговую инструкцию. **Фича не считается протестированной, если Codex не запускал игру или не увидел результат теста.**

Локальное тестирование означает **Play внутри Roblox Studio**, а не отдельный `.exe`, который запускается без Roblox.

## 6. Прототип понравился? Продолжай ту же игру

Открой прежнюю папку проекта и скажи:

```text
$roblox-mvp-builder
Мы проверили MVP, он понравился. Продолжаем ЭТУ ЖЕ игру.
Прочитай Feature Index и текущее состояние проекта.
Составь план P1: серверные сервисы, инвентарь,
прогрессия, сохранения, лобби и тестирование —
только в нужном для этой игры порядке.
Возьми следующую фичу, реализуй и протестируй.
Не пересоздавай сцену и ничего не публикуй без моей команды.
```

После каждой завершённой задачи разработчик должен обновлять документацию со статусом фич и результатами тестов (включая `docs/development-state.md` для возобновления работы). Это позволяет продолжать даже в новой сессии Codex.

## 7. Что умеет GameKit сейчас

**Готовые к подключению заготовки версии 0.1.0:** `core` (запуск модулей), `network` (сетевые события), `tags` (связь объектов мира с логикой), `economy` (валюта), `player-data` (профиль игрока/базовое сохранение). Они **не равны проверенным production-системам**.

**Остальное пока описано как план (`BLUEPRINT.md`):** инвентарь, интеракции, интерфейс, прогрессия, лобби/телепорты, антиэксплойт, аналитика, монетизация, локализация, настройки и другие модули. Codex должен реализовать то, что требуется конкретной игре, и протестировать перед использованием.

Для разработчика: команда создания нового проекта из шаблона (если нужна вручную):

```powershell
python scripts/bootstrap_game.py --target "D:\Roblox\MyGame" --modules core network tags
```

После создания в **папке самой игры** обычно запускают `rokit install`, `rojo plugin install`, `rojo serve`, а в Studio подключают плагин Rojo. Подробнее — [пошаговое руководство](docs/START_HERE_RU.md).

## 8. Важные моменты: безопасность и тестирование с друзьями

- Серверную игровую логику, валюту, награды и проверки нужно держать **на сервере** (`ServerScriptService`), а клиентские запросы перепроверять.
- **Не передавай `.rbxl` друзьям, если не хочешь раскрывать исходники:** этот файл можно открыть и редактировать в Studio. Позже удобнее пригласить друзей в закрытый тестовый Experience, не раздавая файлы проекта.
- Видимые объекты и часть клиентского кода всё равно доступны устройству игрока — полностью скрыть их невозможно.
- Реальные сохранения DataStore, серверные телепорты и монетизация могут потребовать приватно опубликованной тестовой игры и отдельной настройки. **Публикация выполняется только по твоему запросу**.
- Текущие навыки и скрипты ещё нужно проверять на твоём компьютере. Сам факт наличия файла в GitHub не означает, что связь с Studio и автоматическое тестирование уже заработали.

## 9. Где что лежит

| Папка или файл | Для чего |
|---|---|
| `skills/` | Два Codex-скилла: геймдизайнер и разработчик (после PR № 1) |
| `templates/game/` | Стартовые файлы каждой новой игры |
| `modules/` | Готовые модули и черновые описания будущих систем |
| `scripts/` | Скрипт создания проекта и установщик скиллов |
| `docs/START_HERE_RU.md` | Подробные шаги настройки Codex / Studio / Rojo |
| `docs/WORKFLOW_RU.md` | Общая последовательность разработки |
| `docs/CODEX_MASTER_INSTRUCTION_RU.md` | Правила технической работы Codex |
| `module-catalog.json` | Какие модули готовы, а какие только запланированы |

**Коротко:** ты говоришь идею → Codex записывает GDD → делает локальный MVP → ты проверяешь → Codex продолжает **ту же игру** по Feature Index до готового релиза.
